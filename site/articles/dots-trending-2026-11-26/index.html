🔧 开源热榜

github/spec-kit

⭐+120 · GitHub Python 日榜

把需求写成可检查的规格，再拆成实施计划和任务，最后核对实现是否满足原规格。
它还提供独立的想法评估流程，可以先收集证据、决定继续或暂停，不用一开始就进入写代码的流程。

malisper/pgrust

⭐+28 · GitHub Rust 日榜

用 Rust 重写的 PostgreSQL 兼容数据库，面向分析查询设计了向量化执行引擎和即时编译。
查询调度器和统一内存预算是值得看的两个改动：缓冲池、列式缓存和运行中的查询共享预算；项目目前是 Beta，适合在测试数据上比较。

google/perfetto

⭐+5 · GitHub C++ 日榜

把线程调度、CPU 频率和应用埋点放到同一时间线上，可在浏览器本地查看，也可用 SQL 查询追踪数据。
排查一次请求为什么慢时，既能看函数执行了多久，也能把它与线程等待调度、其他进程活动等系统事件对照。

长上下文预填充，什么时候值得改用流水线并行？

2026-11-25·PyTorch / vLLM

vLLM 团队按实测耗时平衡流水线各阶段，再用独立拷贝引擎搬运激活值，减少通信对计算的干扰。
两张 GB300 跑 MiniMax-M3.1-Flash 的长上下文预填充时，双阶段流水线的峰值吞吐最高为对照方案的 1.37 倍；首 token 延迟要求更严时，取舍会变。

用架构图对照 SDXL 的多尺度 U-Net、PixArt 的图像块序列，以及 SD3 让文本与图像 token 双向交互的双流结构。

只听一面之词，助手还能判断对方的动机吗？

2026-11-25 · Google Research

研究者在模拟互动中给一名角色预设动机，助手只看另一名角色转述的经过，再用预设动机核对推断。
实验中，转述者的措辞会左右判断，多问几轮也不总能纠正偏差。这里能核对的是模拟角色的动机，不能用来确认现实中他人的意图。

🔥 热议话题

Marginalia：搜索索引快一点，能多排多少候选？

HN 218 分／82 条评论（抓取时累计）；原文 2026-10-26

独立搜索引擎 Marginalia 正分组件试验把索引从 Java 移到 C++，先改缓冲池和部分倒排索引；理由是同样的查询预算里，索引越快，就越有机会为更多候选打分。
作者尚未决定是否完成迁移，也不预设明显提速；目前更明确的收获是底层内存操作写起来更顺手。

跳到圆周率的某一位：怎样少做一些运算？

HN 74 分／5 条评论（抓取时累计）；原文 2026-11-24

作者重新整理欧拉级数，把分母相同或相关的项合并计算，从而减少提取圆周率十六进制数字所需的除法和完整模幂运算。
这种算法不必先算出前面的所有数字；文中的耗时对比来自作者自己的向量化实现，随目标位数和线程数而异。
HN 讨论

把 Windows 的响度均衡移植到 PipeWire

HN 312 分／173 条评论（抓取时累计）；项目页未标日期

这个项目给应用的播放流加上自动增益，收窄安静和响亮片段之间的音量差；输出端再加一个限幅器，避免放大后削波。
它改变的是整体增益而非某些频段的音色，且目前不处理 JACK 客户端和超过八声道的流。

🔬 科学/人文

核钟、原子云和悬浮磁体，都能用来找暗物质？

Quanta · 2026-11-25 · Jay Bennett

寻找超轻暗物质的实验开始观察不同信号：它若短暂扰动核钟的频率、原子干涉条纹或悬浮磁体的运动，就可能留下线索。
目前这些方法主要用来缩小可能的参数范围，零星异常仍需排除其他来源，尚不足以确认发现暗物质。
