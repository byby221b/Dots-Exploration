压缩文件时，怎样让常见符号少占一点空间？

  3. 今天为何还会混用不同方法？
  4. 可选深入｜历史转向与代价

无损压缩要把原数据一字不差地还原。常见符号可以少占空间，但如果每个符号都必须单独分到整数位，分配就会显得粗糙。把多个符号的编码额度合在一起，能更细地利用频率差异。

主文约4分钟。假设文件只有 A、B 两种符号，每次独立出现，A 的概率为3/4，B为1/4。发送方和接收方已经知道这组概率与文件长度；下面先不计算传递这些信息的额外开销。这是教学模型。

一个符号分一个号码，哪里还可以省？

最直接的办法是 A 写成0，B写成1。每个符号都占1位，频繁出现的A也没得到更短的号码。1952年的Huffman方法，为给定概率分配长短不同的、可以直接接续读取的号码；在逐符号的这类二进制编码里，它已经最优。但这里只有两种符号，两者仍各要1位。[1]

换一个分配单位：把相邻两个符号合成一组。独立条件下，AA的概率是3/4×3/4＝9/16，而BB只有1/16。现在有四种组合，可以给常见组合更短的号码。

一组两个符号概率一套Huffman号码
AA9/160
AB3/1610
BA3/16110
BB1/16111

例如 AABA 分成 AA｜BA，写成0｜110。读到0就确定一组AA，再读110确定一组BA。这些号码都不会是另一个号码的开头，所以连写成0110也能分清。

每组的平均位数为（9×1＋3×2＋3×3＋1×3）／16＝27/16；再除以每组2个符号，得到每个原符号0.84375位，比逐符号的1位更省。个别组合会变长，省的是这个概率模型下的平均值。继续分更大组可以更细，但每组k个二元符号有2的k次方种可能，码表也随之膨胀。

保留一个区间，把整串内容逐步放进去

算术编码把“整串内容是哪一种”表示为一个不断缩小的区间。先把0到1按3∶1分开：A占前3/4，B占后1/4；每读一个符号，都在当前区间里重复同样的划分，保留对应部分。

读到的内容保留下来的区间
尚未开始0 ≤ x < 1
A0 ≤ x < 3/4
AA0 ≤ x < 9/16
AAB27/64 ≤ x < 9/16

看最后一步：AA的区间宽9/16；把它的前3/4留给AAA，后1/4留给AAB，分界就是（9/16）×（3/4）＝27/64。因此一个落在最后区间内的数，例如1/2，配合已知长度3，就能按同样划分依次解出A、A、B。

真正写进文件的是足以确定这个区间的一段二进制信息，还要处理结束位置和有限精度；不能把“1/2写起来很短”当成压缩率。这里的关键是：每个A只把区间缩到原来的3/4，每个B缩到1/4，频率差异能累积到整串内容上，不必替每个A立即凑满1位。

1987年Witten、Neal和Cleary给出了可实际运行的算术编码实现，说明怎样用有限大小的整数和逐步输出处理这个区间。这是实用实现的重要节点，并非算术编码的发明年份。相比查一张简单码表，区间更新与精度管理也带来了实现成本。[2]

今天为何还会混用不同方法？

后来出现的ANS（非对称数系统）改用一个可逆更新的整数状态来积累信息，状态过大时把部分位移到输出中。它同样利用概率不均衡，争取接近算术编码的压缩效果，同时提供不同的计算实现路线；具体速度仍取决于变体、模型与硬件。[3]

现实格式并未只留下一个赢家。2021年的Zstandard格式说明同时使用Huffman与属于ANS家族的FSE：前者可用于压缩没有被重复片段引用替代的字节，后者用于描述片段长度和位置偏移等的符号。格式会结合数据类型与实现成本选方法。[4]

读完可以检查一个变化：若A、B各占一半，上表四种组合就各占1/4；最优的两符号分组号码都长2位，仍是每个原符号1位。这个独立、等概率模型没有可供频率编码利用的偏斜；若数据还含重复片段等结构，则需另外建模。

可选深入｜历史转向与代价

节点改变的单位与代价
1952：Huffman给符号分配完整号码；最优性有逐符号、前缀码的范围。分组可突破每个原符号整数位的限制，但码表增大。
1987：实用算术编码用有限精度实现跨符号区间细分；模型与编码器可分开设计，但需处理区间缩放和输出。
2013／2014：ANS论文不用维护区间两端，而以整数状态积累信息；流式变体可把状态与输出位相互转换，形成另一类实现取舍。
2021：Zstandard格式Huffman与FSE并存；工程格式选择不同数据部分的编码方式，而非全面替换旧方法。

在本例的独立概率模型下，熵是长期平均编码长度的理论基准：H＝−(3/4)log₂(3/4)−(1/4)log₂(1/4)≈0.81128位／符号。log₂表示以2为底的对数。0.84375已经接近它；有限文件还要付出模型、结束标记或初始／最终状态等开销。这里的数值只验证教学模型，没有运行压缩性能测试。

ANS也有数据顺序上的取舍。常见rANS编码状态像栈一样后进先出：最后编码的符号先解出。若希望解码时按原顺序读取，常采用反向编码一个块；当概率依赖前文并需在线更新时，就必须安排模型计算、缓存和分块。这正是今天比较方法时应同时观察压缩率、吞吐、模型开销和访问顺序的原因。[3]

本期追踪的是“怎样把符号概率变成可还原的位串”。它与中间结果删去后重算、存在性过滤、丢失数据恢复所解决的问题不同；同样写着“省空间”，可保留的信息与恢复方式也不同。
