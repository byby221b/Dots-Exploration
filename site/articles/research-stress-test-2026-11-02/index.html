扩大 batch，怎样检验泛化差距的来源

一次参数更新可以同时处理更多样本，多卡训练也就有了更大的并行空间。可如果训练加速了，验证集效果却下降，该先缩回 batch，还是调整训练过程？这是一场有直接实验往来的研究讨论，适合拆成一个能检验的具体问题。

本期审查 Hoffer 等人在 NeurIPS 2017 提出的主张：调整训练过程后，大 batch 可以取得与小 batch 相当的泛化表现。这里的泛化指模型对未参与训练的数据的预测表现。我们关心的是：观察到的差距有多少来自更新次数、学习率和归一化设置，又有哪些差距在这些因素得到控制后仍然存在。[1]

先数清：看了多少数据，改了多少次参数

batch size 是每次更新参数时合并使用的样本数。每个样本给出一个梯度，描述损失随参数变化的方向与幅度；最简单的更新沿负梯度降低损失；训练算法将一批梯度汇总，再更新一次参数。epoch 则表示完整遍历训练集一遍。

用一个只用于算账的例子：训练集有 16,384 条样本，训练 8 个 epoch，最后一批无需补齐或丢弃。

设置每批样本每轮更新总更新总样本处理量
小 batch1281281,024131,072
大 batch，同轮数1,02416128131,072
大 batch，同更新数1,024—1,0241,048,576

两种训练都看过 131,072 个样本，并不意味着参数调整的机会相同。大 batch 将八批样本合成一次更新，更新次数降到八分之一。反过来，让它也更新 1,024 次，就会处理八倍样本。

还可以用两条样本看清“合成一次”的含义。假设只有一个待训练参数 w，两条样本的平方损失分别是 (w−0)²/2 和 (w−2)²/2，从 w=0 出发，学习率为 0.1。学习率控制每次沿梯度移动多远。

先处理第一条，梯度为 0，w 仍为 0；再处理第二条，梯度为 −2，w 更新到 0.2。如果两条合成一批，两个梯度都在 w=0 计算，平均为 −1，只更新一次，w 到 0.1。样本相同，路径已经不同。这只是说明更新过程的差异，尚未涉及验证集，不能由这两个数判断谁泛化更好。

原论文支持什么，后续工作改了什么

Keskar 等人的实验是这场讨论的重要起点。他们在多种分类网络中观察到：大、小 batch 可以取得相近的训练拟合，大 batch 的测试效果仍较差。作者把这一现象与较“尖锐”的极小值联系起来，即参数稍作扰动，损失就明显增加的位置，并提出小 batch 梯度噪声有助于探索较平坦区域的解释。这支持“差距值得认真研究”，也提醒我们仅看训练准确率无法诊断来源；相关性本身尚不能锁定因果机制。[2]

Hoffer 等人直接回应同一问题。他们逐步调整学习率、Ghost Batch Normalization，再延长训练以匹配更新次数。Batch Normalization（批归一化，BN）会利用一组样本的均值和方差归一化中间特征；Ghost BN 将大批分成较小组计算这些统计量，使统计组大小与参数更新批量分开。[1]

原文表 1 的 ResNet44／CIFAR-10 验证准确率如下。小 batch 为 128，大 batch 为 4,096；后三列是在前一设置上继续修改。

小 batch原大 batch加学习率调整再加 Ghost BN再调整训练时长
92.83%86.10%89.30%90.50%93.07%

这是作者报告的一组视觉任务结果。它表明这组大 batch 的差距可以被训练配方消除；最后的提升包含多个改动及额外样本计算，不能全归给“多更新几次”。最接近的已有方案正是这套组合，而非另换模型结构。

Shallue 等人随后在 35 个任务配置中，针对各 batch 分别调整学习率、动量和适用的学习率日程。动量会累积过去的梯度方向，日程规定学习率何时变化。他们未发现大 batch 必然降低样本外表现的证据，但达到目标效果所需的步数会经历收益递减、最终饱和的区间；位置依模型、算法和数据而变。他们也展示了正则化会影响结论。因此，“调好后可以恢复效果”有支持，“只补更新就能解释所有差距”仍然太强。[3]

还有一个测量问题。Dinh 等人指出，对具有 ReLU 等结构的网络，某些保持预测函数不变的参数缩放可以改变通常的尖锐度。若要追踪尖锐度，需先说明采用的参数化和尺度约定；本期把留出集效果作为主判据，把曲率留作辅助诊断。[4]

把主张收窄到一次能做决定的检验

建议审查的局部假设是：对预先选定的数据、网络和优化器，将 batch 从 128 扩到 1,024 后，经过独立调参、固定 BN 统计组并匹配更新次数，大 batch 的验证损失可以恢复到小 batch 的预设容忍范围内。它来自上述公开研究，不是对任何个人项目现状的判断。

先定好容忍差值 δ。δ 表示允许的验证损失差额，应根据任务可接受的实际差额确定；历史运行波动用于规划重复次数和测量精度，看到结果后再改会让判断失去约束。主要比较量是“大 batch 验证损失减去小 batch 验证损失”，数值越大说明大 batch 越差。若没有足够证据把差额限制在 δ 以内，就保留不确定结论。

最低成本的第一步是审计已有配置和日志：global batch 是否按所有设备与梯度累积计算？总更新步数是多少？学习率是在第几步衰减？BN 是每卡独立还是跨卡同步？如果只有 epoch 和最终 AUC，暂时无法区分这些原因。

随后可在公开的小规模分类任务上做一次机制筛查。以下是建议设计，尚未执行；最终业务判断仍要在目标任务复验。

一张实验表，分开两种预算

固定数据划分、网络、损失、数据增强与优化器家族，用同一组随机种子配对比较。小 batch 和大 batch 都获得独立调参机会。设短日程为 128 步、长日程为 1,024 步，对应上面的算账例子。

实验batch更新步数回答的问题
S短128128小 batch 在短日程能到哪里
S长1281,024小 batch 参考结果
L短1,024128与 S长 相同样本处理量时的差距
L长1,0241,024匹配更新数后能否恢复效果

这四组让“batch 大小”和“更新时长”都能单独改变。L短→L长 检查大 batch 延长训练的作用；S短→S长 提供小 batch 的对应变化。S长与L短比较样本预算，S长与L长比较更新预算，分别报告，避免用一个“公平”标签混过去。

调参可从预声明的少量学习率、动量及衰减位置组合开始，各组给予相同候选数量和选型规则，并记录每次搜索消耗的样本数与加速器时长。相同试验次数并不能保证相同算力成本：长日程或大 batch 的单次试验可能更贵。若要回答实际部署预算下的选择，再设一轮固定总加速器时长的搜索；不要把它与机制诊断混成同一张结果表。

为了检验“只是多更新”的更窄说法，先锁定一套稳定配方，只改变更新步数，并把学习率日程按进度比例伸缩；再单列允许重新调参的结果。前者估计这套配方下延长日程的作用，后者衡量允许适配后的可达表现。两者一起看，才知道恢复来自延长训练，还是还需要调整其他条件。

使用 BN 时，主比较固定每个统计组的大小，再补一组让统计组随大 batch 扩大的消融。消融就是有意只改变一个部件，观察结果随之怎样变化。若网络没有 BN，直接省去这一项。梯度累积也要记录：分几次前向计算后合并梯度，与一次大批前向的 BN 统计未必相同。

看哪些结果，何时修改判断

训练中保存三种横轴的曲线：更新步数、累计样本数、实际耗时。每条都同时记录训练损失和验证损失。固定验证检查机会及选型规则，用验证集挑配置，再在预留测试集上作最终比较，避免反复看测试集来选学习率。

先用少量种子筛查，靠近 δ 时按预定规则追加独立重复；不确定性估计同时考虑训练种子波动和留出样本有限。报告均值、离散程度、失败或发散次数，而非只展示最幸运的一次。吞吐量只描述每秒处理多少样本；实际速度应看达到同一质量目标花了多久，目标未达到也要计入结果。

按预先选定的置信水平和估计方法，若 L长 相对 S长 的损失差额置信区间上界不超过 δ，而 L短 稳定落后，就支持“在这个任务中，训练过程适配能恢复效果”。它还不足以证明更新次数是唯一原因，需结合锁定配方与 BN 消融判断。如果只有重新调参后才恢复，结论应改成“恢复依赖配方适配”。

如果训练损失明显落后，先检查优化与日程；如果训练拟合相近而验证损失仍差，优先检查正则化、数据增强及统计组变化。经过预声明的搜索与重复后，若差额区间下界仍超过 δ，就应放弃本次配置下“这套适配足够消除差距”的判断。区间跨过 δ，或搜索的最佳参数仍贴着范围边界时，则继续保持未决，而非宣告主张成立或失败。

若质量已经恢复，但耗时或总成本增加，可达质量的主张得到支持，当前加速方案却没有满足工程目标。模型效果和加速收益各有直接指标，分别下结论更能指导下一步。

带走的判断方法

遇到大 batch 效果下降，先把样本处理量、更新次数和训练配方分开记账，再用同一任务的对照逐项定位。已有研究给出了可恢复的实例，也留下了任务与预算依赖。对推荐训练，这套诊断方式可以迁移；视觉任务中的具体 batch 阈值和准确率不能直接搬过来。

本期新增的是“训练比较怎样控制 batch 与预算”的判断方法，区别于蒸馏教师选择、采样排名评估和激活检查点调度；它们分别讨论监督来源、测量目标与内存调度。
