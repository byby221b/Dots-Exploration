🔧 开源热榜

pytorch/torchtitan

⭐+16 · GitHub Python 日榜

PyTorch 原生的大模型训练框架，用 DeviceMesh 和 DTensor 组合参数分片、张量、流水线、上下文和专家并行，同一份模型定义可覆盖预训练、SFT 与强化学习。
训练配置写成可读的 Python 配方，适合对照研究换一种并行布局时改的是模型、通信，还是训练配置。

kvcache-ai/Mooncake

⭐+12 · GitHub C++ 日榜

Kimi 的服务架构将预填充与逐 token 解码分开，并用共享 KV 缓存池在不同推理实例之间复用前缀。
仓库里可分别看 Mooncake Store 如何供多个实例共享缓存，以及 Transfer Engine 如何在节点间搬运缓存，适合拆解长上下文推理的存储和通信开销。

perspective-dev/perspective

⭐+38 · GitHub Rust 日榜

用于实时数据的表格、透视表与图表组件，可用 WebAssembly 在浏览器运行流式查询，也可把查询交给服务端或现有数据库。
如果要做实时实验监控面板，它支持表格增量更新和视图联动，也能只把可见数据传给浏览器。

🧠 AI/模型

SenseNova-Loop-9B：用层复用增加计算深度

Hugging Face 热门第 9 · Apache-2.0 · 2026-11-17 发布

这款约 9B 参数的图文模型把中间 24 层运行两遍，32 套层权重对应一次前向中的 56 次层计算。
第二遍接着处理第一遍的输出，增加了计算深度，却不用复制参数；部署时仍要按实际执行次数估算开销。

表格模型怎样在单张 GPU 上用上 10 万行上下文？

深度精选·发布日期未核实·ICLR Blogposts 2026

TabPFN 在样本和特征两个维度上做注意力。文章先拆批次绕开 CUDA 网格限制，再分块算 softmax，保留不同块之间的完整注意力。
作者在 TabArena 上无需重训便处理了 10 万行以上的上下文；分块降低峰值显存，但会增加运行时间。

让 Transformer 每层按需读取先前层的输出

2026-11-23 · Google Research · 回顾 ICML 2025 论文

DeepCrossAttention 不把先前层的输出全加进同一条残差流，而是按 token 从多层表示里挑信息，查询、键和值还能各自选。
在 LM1B 的同宽实验里，达到低于 14 的困惑度，标准模型用 42 层，DCA 用 30 层。它只加了不到 0.2% 的参数，但会增加内存带宽开销。
